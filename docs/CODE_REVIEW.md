# 代码检查报告：潜在风险与缺失项

**项目**: ORBWEAVERBOTCODE (PROS V5)  
**检查范围**: `src/main.cpp` 及项目配置  
**日期**: 2025-02-20  
**修复日期**: 2025-02-20（已按报告完成全部修复）  

---

## 一、潜在风险（按严重程度）

### 1. 高：无超时可能导致死循环

| 位置 | 问题 | 建议 |
|------|------|------|
| `driveDistance()` L211 | `while (true)` 无超时、无最大迭代 | 若编码器故障、轮子打滑或目标不可达，会永远不退出。建议加最大时间（如 5s）或最大迭代次数，超时后停止电机并 LCD 提示失败。 |
| `turnToAngle()` L256 | 同上 | 若 IMU 异常或目标角度无法到达，会死循环。同样建议超时 + 失败提示。 |
| `initialize()` L175-177 | `while (imu.is_calibrating())` 无超时 | IMU 若一直处于校准状态会阻塞程序启动。建议加超时（如 5 秒），超时后提示 "IMU CAL FAIL" 并继续或重试。 |

### 2. 中：角度与航向处理

| 位置 | 问题 | 建议 |
|------|------|------|
| `turnToAngle()` L258 | `error = targetDeg - curr` 未归一化到 [-180, 180] | 例如当前 -170°、目标 170° 时 error=340°，会绕长路转。建议将 error 归一化到 [-180, 180] 再参与 PID。 |
| `updateOdometry()` L196 | 使用 `imu.get_rotation()` 直接更新航向 | 若 IMU 跳变（如 179°→-179°），积分会异常。可考虑角速度约束或跳变检测。 |
| `driveDistance()` L229 | `headingError = imu.get_rotation()` 用作直线保持 | 若未在 `initialize()` 或任务开始前将 IMU 置零，直线保持基准可能非零。确认比赛/自洽前是否需 `imu.tare_rotation()`。 |

### 3. 中：资源与硬件假设

| 位置 | 问题 | 建议 |
|------|------|------|
| 全局电机/传感器端口 L18-56 | 端口号与方向（如 -11, -16）硬编码 | 换线或换车需改代码。建议将端口和方向集中到 `main.h` 或 `config.hpp` 常量，并加注释对应实物。 |
| `tube_piston('G', ...)` L18 | ADI 端口 'G' 硬编码 | 确认扩展器与端口与实物一致；多块扩展器时需区分端口命名。 |
| `get_actual_velocity_all()` L348-349 | 依赖 MotorGroup 返回非空 | 已做 `totalMotors > 0` 判断，安全。若电机断线，返回值可能异常，可考虑超时或异常值过滤。 |

### 4. 低：数值与边界

| 位置 | 问题 | 建议 |
|------|------|------|
| `armCounter++` L397 | 每 20ms 自增，长期运行会溢出 | 当前 ARM_*_DURATION 很小，不会溢出。若将来增大时长，可设上限或周期归零。 |
| `drawVelocityGraph` L108 | `GRAPH_LEFT + GRAPH_WIDTH + 8` 等 | 已确认在 V5 屏宽 480 内，无越界。 |
| `driveDistance(0)` | 允许传入 0 | 当前会立即 break，电机不动，行为合理。可文档说明“允许 0 表示不移动”。 |

### 5. 低：PROS 竞赛回调

| 位置 | 问题 | 建议 |
|------|------|------|
| `main.h` 声明 | `disabled()`、`competition_initialize()` 在 main.h 中声明 | 若 PROS 内核未提供默认空实现，链接可能报未定义引用。若当前能正常编译，可保留；否则在 `main.cpp` 中补空实现。 |

## 二、缺失项

### 1. 逻辑/功能缺失

- **disabled()**：未实现。若需要在禁用时停止电机、收起机构或清屏，应实现并停止所有电机/气动。
- **competition_initialize()**：未实现。若需要在比赛开始前做一次性初始化（如 LCD、气动初始状态），可在此实现。
- **自洽路径**：`autonomous()` 仅做简单 24in → 90° → 12in + intake，无分支、无传感器判断、无失败恢复，可按赛题扩展。

### 2. 错误与健壮性

- **传感器故障**：未检测编码器/IMU 断线或异常值；建议在关键循环中增加“长时间无变化/超范围则报错并退出”。
- **手柄断连**：opcontrol 已有 3 秒等待和 `connected` 检查并置零电机，逻辑完整；可考虑在断连时让气动/翼保持当前状态还是收回（当前为保持）。
- **电机堵转/过流**：未做电流或温度检测，无法在代码层做保护（若硬件支持可后续加）。

### 3. 可维护性

- **魔数**：如 `1.2`（L230 直线保持）、`90.0`/`100.0`（功率限幅）、`0.5`/`1.0`（误差阈值）建议改为命名常量并集中放在文件顶部，注释用途。
- **端口与机械常数**：建议单独 `config.hpp` 或 `main.h` 区段，列出轮径、端口、PID 默认值等，便于调参和换车。
- **注释**：关键 PID、odom 公式已有注释；建议为 `autonomous()` 各步骤和按键布局补简短注释或单独 README。

### 4. 文档与版本

- **README**：项目根目录无 README 时，建议简要说明：如何编译、键位、自洽流程、端口与机械常数位置。
- **.DS_Store**：已在 .gitignore 中，若仍被跟踪，可执行 `git rm --cached .DS_Store` 一次以从版本库移除。

---

## 三、建议修复优先级

1. **必做**：为 `driveDistance`、`turnToAngle`、`initialize` 中 IMU 校准循环增加超时与失败处理，避免死循环与无法启动。
2. **推荐**：实现 `disabled()`（至少停止所有电机）；`turnToAngle` 角度误差归一化到 [-180, 180]。
3. **可选**：实现 `competition_initialize()`；将魔数与端口集中配置；为自洽和键位写简短文档。

---

## 四、总结

- **优点**：opcontrol 手柄断连保护、积分限幅、速度曲线显示、环形缓冲绘图、左右电机方向与平均速度处理正确。
- **主要风险**：无超时的 `while(true)` 和 IMU 校准阻塞；角度未归一化可能绕远路。
- **缺失**：`disabled`/`competition_initialize` 未实现；传感器异常与配置集中化不足。

按上述优先级逐步修补后，可显著提高比赛中的可靠性和可维护性。
